# 숲속의 모찌 (Mori no Mochi)

누르는 시간만큼 멀리 뛰는 모찌가 아이소메트릭 숲의 그루터기를 밟고 전진한다.
정중앙에 착지하면 Perfect 보너스가 연속으로 쌓이는 원터치 차지 점프 게임.

위챗 跳一跳 / Ketchapp Stack Jump 계보. 메커닉은 검증된 공식이고
승부는 차지→점프의 손맛과 톤에서 난다.

사양은 [GDD.md](GDD.md)에 있다. 이 문서는 코드를 만지는 사람을 위한 것이다.

## 돌리기

```bash
npm install
npm run dev      # 개발 서버
npm test         # 테스트 18개
npm run build    # 타입체크 + 번들 (gzip 약 9KB)
npm run preview  # 빌드 결과 확인
```

조작은 하나다. **꾹 눌렀다 떼면 점프.** 데스크톱에서는 스페이스바도 같다.

### 개발용 URL 플래그

| 플래그 | 하는 일 |
|---|---|
| `?debug=1` | fps / 렌더 시간 / 상태, 퍼펙트 반경(초록 타원), 목표선, `window.__world()` |
| `?debug=1&slow=6` | 시간을 6배 느리게. 0.5초 안에 끝나는 연출을 눈으로 보려면 필요하다 |

`debug` 없이는 전부 꺼지고 `__world` 도 노출되지 않는다.

## 구조

**점프·판정·스코어는 순수 함수다. 렌더는 월드를 읽기만 한다.**
덕분에 테스트가 DOM 없이 Node 에서 돈다.

```
src/
  config.ts          튜닝 상수 단일 소스. 숫자를 바꾸려면 여기만 본다
  main.ts            부팅, 입력, 화면 전환(타이틀 ↔ 플레이 ↔ 결과)
  engine/
    loop.ts          고정 타임스텝(물리 60Hz) + 렌더 보간 alpha.
                     120Hz 화면에서는 두 스텝 사이를 world.interpolate() 로 섞는다
    canvas.ts        디자인 공간 390x844 를 contain 으로 맞추는 스케일러.
                     레터박스 범위(bleed)와 노치 여백(safe)을 노출한다
    ease.ts  rng.ts  보간 유틸 / 결정적 난수
  game/              ← 렌더를 모른다
    iso.ts           아이소 투영
    jump.ts          차지→거리, 체공시간, 포물선      (순수)
    judge.ts         착지 판정 perfect / ok / miss      (순수)
    score.ts         그루터기·퍼펙트·콤보 점수          (순수)
    spawn.ts         절차적 그루터기 생성               (순수)
    camera.ts        추종                               (순수)
    world.ts         상태 기계와 한 스텝 전진
    session.ts       localStorage 기록
  render/            ← 월드를 읽기만 한다
    ground.ts        바닥 패턴과 비네트
    scene.ts         그루터기·모찌 그리기(원점 기준)
    sprites.ts       그루터기를 비트맵으로 구워 캐시
    world.ts         깊이 정렬해서 월드 한 장
    hud.ts  result.ts  title.ts  share.ts  debug.ts
test/
  score.test.ts      스코어 공식 역산
  world.test.ts      무한 진행, 회수, 난이도, 도달 가능성, 카메라
  feel.test.ts       판정 창이 사람 손에 맞는 크기인지
```

## 알아두면 좋은 결정들

전부 원작 영상(`ref/source.mp4`)을 뜯어서 정한 것이다.

**투영 부호.** GDD §4 식은 `+x`/`+y` 둘 다 화면 아래로 내려가는데 영상은
반대다. screenY 를 뒤집어 `+x` = 우상향, `+y` = 좌상향으로 쓴다.

**스코어 공식.** 퍼펙트 점수 = `10 × 현재 연속 횟수`, 상한 없음.
영상에서 `Perfect ×N` 라벨을 프레임별로 읽어 연속 패턴 `[3,3,1,1]` 을
복원했고 결과 카드의 120 / +140 / 260 과 정확히 맞는다.
`test/score.test.ts` 가 이걸 고정한다.

**차지 스쿼시만 선형이다.** 스쿼시는 애니메이션이 아니라 게이지다.
거리와 비례해야 플레이어가 읽는다. 시간 기반 연출은 전부 ease-out.

**차지 범위가 생성 범위보다 넓다.** 원작처럼 앞쪽 길이 보이려면 그루터기를
4개씩 미리 만들어야 하고, 그러면 기준이 착지 지점이 아니라 직전 그루터기
중심이 된다. 착지 오차가 필요 거리를 최대 ±반지름만큼 흔들어서,
생성 `[2.3, 4.3]` 을 차지 `[1.3, 5.3]` 이 덮는다. 도달 불가가 생기지 않는다.

**그루터기는 비트맵으로 굽는다.** 매 프레임 그라디언트를 만들면 63fps 로
떨어졌다. 종류가 반지름 3 × 높이 2 × 결 변주 4 뿐이라 전부 캐시한다.
기기 픽셀에 1:1 로 굽고 스케일이 바뀌면 버린다. 바닥 패턴도 같다.

**차지 중 포커스를 잃으면 차지를 버린다.** `pointerup` 이 영영 안 올 수 있고,
돌아와서 떼는 순간 최대 점프가 나가면 그대로 죽는다.

## 손맛을 만질 때

`src/config.ts` 만 보면 된다. 다른 파일에 리터럴 상수는 없다.

제일 먼저 만져볼 값은 `CHARGE_TIME`(0 → 최대 차지까지의 시간)이다.
차지가 시간에 선형이라 판정 창은 그대로 "눌러야 하는 시간의 폭"이 된다.

```
반지름 1.00 → 퍼펙트 143ms, 착지 475ms
반지름 0.86 → 퍼펙트 123ms, 착지 409ms
반지름 0.72 → 퍼펙트 103ms, 착지 342ms
```

`test/feel.test.ts` 가 이 창이 사람이 맞출 수 있는 범위를 벗어나면 알려 준다.

## 일부러 안 넣은 것

사운드, 캐릭터 스킨·상점·과금, 앱인토스 SDK 연동.
원작 우상단의 사운드 버튼 자리는 비워 뒀다. 동작하지 않는 버튼을 두는 것보다 낫다.
타이틀의 `개인정보처리방침` 은 연결할 페이지가 없어 글자만 있다.

**원작 에셋은 추출·복제하지 않았다.** `ref/` 의 영상은 메커닉·레이아웃·톤 참고용이다.
